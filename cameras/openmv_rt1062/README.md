# openmv_rt1062 — "owlcam"

An **OpenMV Cam RT1062 (R6)** yard camera: the reference implementation of
[`docs/camera_standard.md`](../../docs/camera_standard.md). Motion diff at
VGA, recorded frames as full-resolution 2592x1944 JPEGs (OV5640 native,
encoded on the sensor), delivered through sensorhub's blob gate (LAN or the
Tailscale Funnel), telemetry over the same gate, config and firmware pulled
from sensorhub, a setup mode with a phone page, one control port.
Board serial `e606fe64d7090732`, firmware 4.8.1 (MicroPython 1.26).

**Status: live** (app 2.0.4-rt, 2026-09-03), reporting as `rt1062cam`:
http://192.168.86.26:8088/d/rt1062cam. No SD card is inserted, so the
spool is inactive (`sd: false` in `/status`); frames that fail to upload
are counted in `failed` and lost.

Case: [`case/`](case/) — drip-resistant cup + back plate, 1/4-20 insert; the
lens focus ring is reachable inside the hood.

## Deploy

Everything starts from `~/.dusty/config.toml` `[camera.openmv_rt1062]` and
`~/.dusty/secrets.toml`:

```bash
tools/dustygen cameras/openmv_rt1062 --public --stage
```

writes `software/app/secrets.py`, stamps `TUNING` into `board.py`, publishes
the same tuning to `/hd2/sensorhub/config/rt1062cam.json` (bumping `cfg`
when it changed), bundles `software/build/app.py`, and stages it as
`/hd2/sensorhub/firmware/rt1062cam.py` + `.version`. The board pulls a new
`cfg` at boot, every `heartbeat_s`, and on the setup page's **refresh**;
it pulls firmware whose `.version` differs from its `APP_VERSION` and is
not blacklisted, installs with `app_prev.py` kept, and marks the install
good after its first successful upload (`fw_pending` in `/status`). A
build that crashes at import is rolled back by the loader and blacklisted
in `/flash/fw_bad.txt`.

- **Bump `APP_VERSION`** in `board.py` for every staged build, or the board
  will not pull it.
- **Fast path on the LAN:** `python3 software/host/ota_push.py --ip <camera ip>`
  pushes the bundle immediately (no prove-out).
- **Credentials/endpoints** (`secrets.py`) and the loader go over USB only,
  as in "First deploy" below.

### First deploy (USB)

The board mounts as `/media/wroscoe/OPENMV` and enumerates as
`/dev/serial/by-id/usb-MicroPython_Board_in_FS_mode_e606fe64d7090732-if00`.

```bash
D=/media/wroscoe/OPENMV; A=software/app
cp $A/secrets.py $D/secrets.py; cp $A/ota.py $D/ota.py; cp $A/ota_main.py $D/main.py
cp software/build/app.py $D/app.py; sync
udisksctl unmount -b /dev/sdX          # whichever the OPENMV drive is
mpremote connect /dev/serial/by-id/usb-MicroPython_Board*-if00 reset
```

## Control port (:8266)

| Endpoint | |
|---|---|
| `GET /status` | JSON: version, mode, cfg, uptime, counters (`sent`, `failed`, `pending`, `seq`), `sd`, `fw_pending`, `rolled_back`, `last_error`, `last_capture`, sensors, setup-session stats, per-stage `max_ms`. |
| `GET /setup` | The phone page: grayscale VGA stream with the sharpness score, **shoot**, **refresh config**, live/restart links, a watchdog that reopens the stream if it stalls. |
| `GET /stream?secs=N` | The MJPEG stream (starts a setup session). |
| `GET /live` | End setup mode now. |
| `POST /shoot` | Capture and deliver one full-res frame (`why: manual`). |
| `POST /refresh` | Pull config + check firmware now. |
| `POST /update` | Push OTA (`x-token`). |

Linked as **Owlcam focus** on http://homegpu/ and as **setup** on the
sensorhub device page.

## Setup mode

Enter: the setup page, the user button (`SW`, next to reset on the top
edge, through the roof chimney; hold 300 ms; blue LED on while active), or
`mode = "setup"` in the server config. Leave: `setup_secs` timeout, `/live`,
the button, closing the page (30 s grace), or the config flipping back.
Recording pauses; telemetry continues only while no viewer is attached (a
TLS publish blocks the stream for seconds); on exit the motion reference is
reset and one confirmation frame is delivered. The score is the stdev of a
x4 Laplacian over the boxed centre ROI: scene-dependent, so focus in
daylight and judge by the peak (a soft lens read 16 at midday, 4 at dusk,
0 at night).

## Standard mapping (docs/camera_standard.md, 2026-09-03)

| Stage / feature | How |
|---|---|
| Boot | `fw_boot_check` (prove-out / blacklist), `cfg_init` (stamped defaults + stored server config), boot counter; loader recovery mode |
| Connect | WiFi (retry every 30 s), NTP by the loader, `ip` in meta |
| Announce | one forced telemetry at boot |
| Sense | `CHG` pin (charging), RSSI |
| Watch | VGA RGB565 diff vs the last recorded frame (`motion.py`); heartbeat timer |
| Capture | WQXGA2 sensor-side JPEG, VGA software-JPEG fallback (`camera.py`) |
| Judge | not applicable on-device: the server analyzer runs on every frame |
| Record | standard meta `ts seq w h v cfg ip mode why diff gate heartbeat buffered` |
| Deliver | blob gate, TLS on the Funnel; spool + streamed drain when a card is present (none today) |
| Report | `/telemetry` every `telemetry_s`: uptime, mem_free, boot_count, counters, diff stats, mode, cfg, charging, rssi |
| Serve | one port; config pull + firmware pull every `heartbeat_s` and on refresh; push OTA kept |
| Rest | idle loop keeps the preview fresh and polls the control port every 100 ms |
| Setup mode | as above; `why: manual` for shoot and the confirmation frame |
| Tests | `tests/test_rt1062_app.py` (meta keys, why vocabulary, tuning keys) + `cameras/common/tests` |

Proven 2026-09-03 on the live camera: config pull without reflash
(cfg 1 → 2 → 3), pull OTA 2.0 → 2.0.1 → 2.0.3 → 2.0.4, and rollback of a
deliberately crashing 2.0.2 (blacklisted, not re-pulled). Not yet proven:
spool and drain (no SD card), a full day of heartbeats on 2.x.

## Firmware facts (4.8.1)

- Has `mqtt`, `ntptime`, `ssl` (`SSLContext`, `CERT_NONE`; no CA bundle),
  `network.WLAN`, `image.to_jpeg`, histogram `l_bins`, `machine.LED`,
  `machine.Pin.board.SW` (user button, active-low) and `CHG`. No `imu`,
  no `cpufreq`, no `BAT_ADC`.
- Frame buffer 13 MB, fb_alloc 10 MB, GC heap 8 MB. A full-res RGB565 frame
  would be 10 MB, hence sensor-side JPEG for captures.
- Every OV5640 framesize from QVGA up initialises; `sensor.JPEG` at WQXGA2
  gives ~560 kB at quality 85 by day, ~100 kB at night.
- Direct MQTT from the board is off: the shared credential may not write
  `rt1062cam/#`, and a rejected QoS-0 publish is dropped silently. The gate
  publishes as `ingest`.
- `get_statistics().l_stdev()` on grayscale is integer-valued (hence the x4
  Laplacian in the focus score).
